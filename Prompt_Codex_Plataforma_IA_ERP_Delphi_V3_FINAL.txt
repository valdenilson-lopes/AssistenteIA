Você é um agente de desenvolvimento trabalhando em um ERP legado/moderno desenvolvido em Delphi VCL, com banco de dados Oracle e acesso via FireDAC.

Sua missão é implementar uma PLATAFORMA DE IA CORPORATIVA integrada ao ERP.

IMPORTANTE:
Não trate este projeto como a simples criação de um chatbot.
O objetivo é criar uma camada de inteligência nativa do ERP, inicialmente SOMENTE PARA CONSULTA, que possa:
- responder perguntas sobre dados atuais do ERP;
- responder perguntas sobre funcionamento, rotinas e regras do sistema;
- consultar fontes autorizadas do banco;
- utilizar documentação interna como conhecimento;
- reconhecer quando não sabe uma resposta;
- solicitar/registrar novo conhecimento;
- aprender por meio de documentos aprovados e indexados;
- evoluir módulo a módulo;
- funcionar sem que todo o projeto Delphi precise ser fornecido de uma vez;
- ser econômica no consumo de tokens;
- permanecer desacoplada do provedor de IA.

======================================================================
1. OBJETIVO GERAL
======================================================================

Permitir que o usuário, dentro do ERP Delphi, faça perguntas em linguagem natural, por exemplo:

- Quanto vendemos hoje?
- Qual vendedor vendeu mais este mês?
- Quais produtos estão com estoque baixo?
- Quanto temos de contas a receber vencidas?
- Quais títulos PIX estão pendentes de conciliação?
- Como faço determinada operação na rotina 9003?
- O que significa determinado campo?
- Como funciona determinada regra do Financeiro?

O assistente deve responder EXCLUSIVAMENTE sobre:
- ERP;
- dados disponibilizados pelo ERP;
- documentação interna;
- regras e rotinas documentadas;
- informações obtidas por ferramentas autorizadas.

Não habilitar navegação web para o usuário final.

======================================================================

NUNCA invente:

5. informe objetivamente quais arquivos, tabelas, campos ou regras precisam ser fornecidos;

3. RESTRIÇÕES FUNDAMENTAIS
======================================================================

1. MVP SOMENTE LEITURA.

2. Não permitir:
   INSERT
   UPDATE
   DELETE
   MERGE
   ALTER
   DROP
   CREATE
   TRUNCATE
   EXECUTE
   GRANT
   REVOKE
   ou procedures que alterem dados.

4. Segurança de:
   - empresa;
   - filial;
   - usuário;
   - permissões;
   deve ser aplicada pelo ERP/API/camada de dados.
   NUNCA confiar apenas no modelo.

5. Não enviar schema completo do banco em cada pergunta.

6. Não enviar toda a documentação em cada pergunta.

7. Não enviar todo o histórico de conversas indefinidamente.

8. Nunca colocar a API key/token da OpenAI dentro do executável Delphi distribuído.

9. A IA nunca deve inventar uma resposta quando não possuir informação suficiente.

10. Dados atuais devem vir de consulta/ferramenta.
    Nunca tratar conhecimento antigo do modelo como dado atual do ERP.

11. FLUXO "QUERO APRENDER"
======================================================================

Esse fluxo é requisito central.

Quando a IA não tiver conhecimento suficiente, NÃO inventar.

Retornar estado estruturado:

knowledge_sufficient = false

e mensagem amigável semelhante a:

"Ainda não tenho conhecimento suficiente sobre este assunto no ERP.
Posso aprender quando a documentação correspondente for adicionada
ao Centro de Conhecimento."

Na tela, disponibilizar para usuários autorizados:

[ ENSINAR A IA ]

O usuário/desenvolvimento poderá:
- anexar documento;
- escrever texto;
- informar módulo;
- informar assunto;
- adicionar observações.

O conteúdo NÃO entra imediatamente na base de produção.

Fluxo:

NOVO CONHECIMENTO
    ->
PENDENTE
    ->
REVISÃO
    ->
APROVAÇÃO
    ->
INDEXAÇÃO
    ->
DISPONÍVEL PARA A IA

A IA pode SUGERIR módulo e assunto.
A aprovação final pertence ao ERP/usuário autorizado.

======================================================================
15. RECUPERAÇÃO SELETIVA / RAG
======================================================================

NÃO carregar toda a base de conhecimento a cada pergunta.

Fluxo:

PERGUNTA
    ->
DETECTAR DOMÍNIO/INTENÇÃO
    ->
BUSCAR SOMENTE CONHECIMENTO RELEVANTE
    ->
ENVIAR PEQUENO CONTEXTO AO MODELO

Exemplo:

Pergunta:
"Quanto tenho de contas a receber vencidas?"

Domínio:
Financeiro

Recuperar:
- documentação relevante de Financeiro;
- View BI correspondente, se existir;
- regras necessárias de contas a receber.

NÃO recuperar:
- Estoque;
- PIX;
- Fiscal;
- Tributação;
- documentação irrelevante.

Criar interface conceitual:

IConhecimentoERP

permitindo implementações:
- local/simples;
- vector store;
- busca semântica;
- outro mecanismo futuro.

17. DADOS VIVOS X CONHECIMENTO
======================================================================

PERGUNTA DE CONHECIMENTO:

Resposta:
Centro de Conhecimento.

PERGUNTA DE DADO ATUAL:
"Quanto vendemos hoje?"

Resposta:

PERGUNTA HÍBRIDA:
"Por que determinado valor aparece assim?"

Pode exigir:

- consulta;
- interpretação combinada.

Nunca afirmar valor atual sem consultar a fonte apropriada.

18. MODELO HÍBRIDO DE CONSULTAS
======================================================================

Suportar dois caminhos.

CAMINHO 1 — OPERAÇÕES CONHECIDAS

- vendas.por_produto
- estoque.saldo
- estoque.abaixo_minimo
- financeiro.receber
- financeiro.vencidos
- pix.pendentes

Essas operações usam SQL previamente validado.

A IA apenas identifica:
- operação;
- parâmetros.

Esse deve ser o caminho preferencial.

CAMINHO 2 — PERGUNTA AD HOC

Quando não existir operação conhecida:

1. detectar domínio;
2. recuperar documentação relevante;
3. recuperar schema/Views autorizadas relevantes;
4. solicitar SELECT;
5. validar SELECT;
6. aplicar escopo obrigatório;
7. executar;
8. limitar resultado;
9. devolver dados ao modelo;
10. gerar resposta natural.
